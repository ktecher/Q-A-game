Q&A Game · UI Study

The /question screen,
uncrowded.

One faithful snapshot of the screen today, then four ways to make it neat, calm, and easy to follow — same brand, same content, fewer competing boxes. No code changed; these are static mockups to choose from.

Why it feels crowded

10

bordered blocks stacked head-to-toe — four info panels and six tap targets — each with its own frame, gradient, and an Arabic + English label. The actual question, the one thing that matters, sits fifth from the top.

keep — earns its space merge — combine or shrink cut — remove or demote
  1. 1Stage banner — long bilingual sentence in a pill, plus a separate exit button.
  2. 2Team tracker — two large status cards + a "vs", each repeating name, English name, and a status line.
  3. 3Category row — chip, English caption, and value, three type styles fighting on one line.
  4. 4Dual timer — a full bordered block for two numbers, as heavy as the question card.
  5. 5Question card — the hero, but buried below four blocks.
  6. 6Lifelines — three big buttons, each an icon over two lines of text.
  7. 7Action row — three more two-line buttons; Reveal doesn't stand out from Pause.

Each artboard renders the real answer phase — Falcons vs. Eagles, a 400-point history question. Compare density, then pick a lane.

A · Focus FlowSlim HUD on top, question is the hero

Option A

Everything above the question collapses into two thin lines. The card grows and centers. English drops to quiet captions. Lowest-risk — same layout, less weight.

Recommendation. A · Focus Flow is the safe, high-impact pick — it removes the most visual weight while keeping the exact structure the code already renders, so it maps to the smallest diff. B · Command HUD is the strongest if you want it to feel like a broadcast game show. C pays off on projectors/tablets; D is the calmest but hides the opposing-team detail behind a badge.
All four keep the pause / end-turn / reveal actions, both lifelines, the RTL Arabic-first hierarchy, and the gold-on-ink identity. Reveal-and-award (Stage 2) is unchanged and not shown. Static mockups only — no application code was modified.
